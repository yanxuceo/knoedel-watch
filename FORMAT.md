# Deck format v1

One **deck** is one episode: about 12 cards on one theme, with one character. A deck is a single JSON file that every player (the round-screen firmware, the web preview, future players) reads, so content is written once.

The copy of this folder in the firmware repository is the source of truth. Changes go through the changelog at the end of this file.

```
FORMAT.md                         this document
deck.schema.json                  machine-readable structure
registry/<character>.json         what the firmware can draw (maintained by firmware)
theme.json                        fixed colours for gender, prefix, reflexive, aux, case
tools/deckfmt.py                  shared rules: markup, grammar line, spoken text, registry lookup
tools/check_deck.py               validation, run by content authors and by the importer
tools/make_audio.py               German audio + audio/manifest.json
tools/voices.json                 TTS provider, voice ids, speed, file format
tools/build_preview.py            web preview of a deck (tools/preview/player.html is its template)
tools/preview/<character>.js      drawing reference of each character (knoedel.js, katze.js, dinge.js)
tools/import_decks.py             firmware import: checks, audio, pixel fit, device assets
content/library.json              the content pack: its name and its decks, in device order
content/<deck-id>/deck.json       the deck: the only file content authors write
content/<deck-id>/audio/          generated from deck.json, never written by hand
content/<deck-id>/preview.html    generated by build_preview.py, not committed
```

**Handoff to the firmware is exactly one folder: `content/<deck-id>/`.** The importer reads `deck.json` and `audio/` for all text and audio. A deck that needs new animation ids also comes with a web preview, which is the **drawing reference** for those ids (see "Animation"), never a source of text.

German is the source language. Everything that explains German to a learner (gloss, translation, tip) is a map keyed by locale, so adding a language means adding keys, not changing the format.

## Faces on the device

A tap cycles through the faces of a card. A face with no content is skipped.

| Face | Shows | Fields |
|---|---|---|
| 1 Front | animation, headword, short meaning | `anim`, `style`, `lead`, article (nouns), `headword`, `gloss[locale]` |
| 2 Example | grammar line, example, translation | grammar line (see below), `example.de`, `example.translations[locale]` |
| 3 Tip | extra grammar line (if any), pitfall | `pattern` when not used on face 2, `tip[locale]` |

The device shows German plus **one** locale at a time. The firmware carries two locales; the learner picks one in the watch's settings. It never shows two translations at once.

### Grammar line on face 2, by part of speech

| `pos` | Face 2 grammar line | Example | `pattern`, if present, goes to |
|---|---|---|---|
| `verb` | Präteritum · Perfekt (`hat` / `ist` coloured from `aux`) | `stand auf · ist aufgestanden` | face 3 |
| `noun` | plural | `die Wolken` (omitted if `plural` is `null`) | face 3 |
| other | `pattern` + case chip | `stolz auf` `+ Akk` | – |

On face 1, nouns show the article in the gender colour before the headword: **die** Sonne. The article is taken from `noun.article` and never written into `headword`.

`deckfmt.grammar_line(card)` and `deckfmt.face3_pattern(card)` implement this table; players and the audio script use them rather than re-implementing the rule.

## Deck fields

| Field | Required | Notes |
|---|---|---|
| `format` | yes | `1`. |
| `id` | yes | Lowercase ASCII slug, never changes once published (`gefuehle`). |
| `version` | yes | Semver of the content. Patch for typos, minor for new or changed cards. |
| `episode` | no | Number in the series. |
| `title` | yes | Map, `de` required. |
| `level` | yes | `A2`, `A2-B1`, … |
| `character` | yes | Must have a `registry/<character>.json`: `knoedel` (adjectives, expressions), `katze` (verbs; the cat's name is Brezel, her id stays `katze`) or `dinge` (nouns: the thing alone). |
| `locales` | yes | Locales that are complete in every card (`zh-Hans`, `en`). |
| `license` | no | Content licence, default `CC-BY-NC-SA-4.0`. |
| `review` | no | Notes for authors: `status` (`draft` → `in_review` → `reviewed`), reviewer, date. Nothing depends on it: decks are published as they are and corrected in a new pack when a mistake is found. |
| `cards` | yes | In display order. 12 recommended (progress ring). |

## Card fields

| Field | Required | Notes |
|---|---|---|
| `id` | yes | ASCII slug, unique in the deck (`ueberrascht`). Also the audio file prefix. |
| `pos` | yes | `adjective`, `verb`, `noun`, `phrase`, `preposition`, `adverb`. |
| `lead` | no | Small text above the headword: `sich`, `sich die Zähne`, `Kaffee`. |
| `headword` | yes | Markup allowed: `{{auf\|prefix}}stehen`. |
| `gloss` | yes | Short meaning per locale. |
| `pattern` | no | `{ "text": "stolz auf", "case": "Akk" }`, `case` is `Akk`, `Dat`, `Gen` or `null`. Must be visible in `example.de` (the checker warns otherwise). A related construction the example does not use, such as *sich erkälten* next to *Ich bin erkältet*, goes into `tip`. |
| `noun` | nouns | `{ "article": "der", "plural": "Schr{{ä|pl}}nk{{e|pl}}" }`, plural without article, `null` if none or rare. Mark what changes in the plural with `{{…|pl}}` (umlaut, ending); players show it in the gender colour. |
| `verb` | verbs | `reflexive` (`acc`, `dat`, `null`), `praeteritum` (3rd sg., markup allowed), `perfekt: { aux: "haben" \| "sein", rest }`. `aux` is never written into `rest`. |
| `example` | yes | `de` (markup allowed) and `translations` per locale. A line break (`\n`) starts a new line, used for the two turns of a mini dialogue (`– Danke! \n– Gern geschehen!`); it is not spoken. |
| `tip` | no | Pitfall per locale. Written for each audience, not translated. Markup allowed for German fragments. |
| `style` | yes | `color` (accent) and `background` (animation disc). Both required. |
| `anim` | yes | See "Animation". |
| `notes` | no | Editor notes, never displayed. |

Verb example: `sich die Zähne putzen` is `lead: "sich die Zähne"`, `headword: "putzen"`, `verb: { reflexive: "dat", praeteritum: "putzte sich die Zähne", perfekt: { aux: "haben", rest: "sich die Zähne geputzt" } }`.

## Inline markup

Allowed in `headword`, `verb.praeteritum`, `verb.perfekt.rest`, `example.de` and `tip`.

| Markup | Meaning |
|---|---|
| `{{glücklich über}}` | keyword of the card, accent colour |
| `{{auf\|prefix}}` | separable prefix |
| `{{mir\|refl}}` | reflexive pronoun |
| `{{ä\|pl}}` | the part of a noun plural that changes (only in `noun.plural`) |

Unknown roles render as plain text. Glosses and translations contain no markup.

## Colours

Grammar colours are fixed for the whole project and stored in `theme.json`, with a `light` set (web) and a `dark` set (black round screen). Players read that file instead of choosing their own.

| Role | Light | Dark |
|---|---|---|
| article der / die / das | `#2F6BD6` / `#D6435E` / `#B7791F` | `#7FA6F5` / `#FF7E95` / `#FFC24A` |
| separable prefix | `#D9620F` | `#FF9F43` |
| reflexive pronoun | `#0E8C7E` | `#4FD1BF` |
| aux hat / ist | `#2A5FC4` / `#D2402A` | `#86A9F5` / `#FF8468` |
| case chip Akk / Dat / Gen | `#E1601A` / `#13946A` / `#7A4FD6` | `#FF8A47` / `#3CCB98` / `#B394FF` |

The card keyword (`{{…}}` without a role) and the headword use the card's own `style.color`.

## Locales

BCP-47 tags: `zh-Hans`, `en`. `zh-Hans` rather than `zh-CN`, so `zh-Hant` can be added later. A tip explains a pitfall from the learner's own language, so each locale's tip is written separately: *so … dass* is "……得……" for Chinese speakers and "so … that" for English speakers.

## Text budgets

Character counts after stripping markup. **They are guidance for authors**: `check_deck.py` warns, it does not fail (unless `--strict`). The authoritative check is the importer, which measures every string in pixels with the real fonts and refuses what does not fit.

| Field | Budget | Face |
|---|---|---|
| `headword` | 12 (nouns with article: 16; players shrink longer headwords) | 1 |
| `lead` | 16 | 1 |
| `gloss` | zh-Hans 8, en 20 | 1 |
| grammar line / `pattern.text` | 18 | 2 |
| `example.de` | 85 (four lines) | 2 |
| `example.translations` | zh-Hans 24, en 60 | 2 |
| `tip` | zh-Hans 36, en 70 | 3 |

On a round screen lines shorten towards the edges: prefer examples without very long words, and with four lines of similar length.

## Animation

The firmware draws the character from data. A deck refers to ids from `registry/<character>.json`; the registry lists only what the firmware has **actually implemented**. `check_deck.py` compares the two and prints every id the deck needs that is not implemented yet. That list is the firmware's to-do for the deck.

```json
"anim": {
  "pose":   { "happy": 1, "smile": 1, "armL": 150, "armR": 150 },
  "tint":   null,
  "motion": ["bounce"],
  "fx":     ["confetti"],
  "props":  [],
  "bubble": "house"
}
```

- `pose`: target values that differ from neutral. Only parameters listed in the registry. The player positions the character, so `x` and `y` are not pose parameters.
- `tint`: colour the body blends towards (by the `tint` pose value), or `null`.
- `motion`, `fx`: lists of ids, freely combinable.
- `props`: objects the character holds or that stand on the stage: a sponge in the paw, a vacuum whose head touches the floor, a washing machine next to the cat. Each prop id defines where it attaches (`hand`: drawn between arm and paw and moved by the paws; `wear`: on the body, under the arms; `behind`: on the body, behind the torso, e.g. a backpack; `back`: standing on the stage behind the character; `front`: on the stage in front of the character, e.g. lake water or a table). Props are drawn in list order within their layer. Unlike the bubble, props are **required**: a verb card does not read without them.
- `character`: optional, draws this card with another character than the deck's (needs that character's registry).
- `bubble`: thought-bubble icon, or `null`. Optional for the player: a card must read well without it.

### Noun cards

Noun decks use the character `dinge`: the front face shows the thing alone, centred, with a small idle movement (a fridge door opens, a lamp flickers), on a background in the gender colour of the noun (`style.background`: der `#DCE6F7`, die `#FBE1E7`, das `#FFF0C9`; `style.color` is the light gender colour). The object is the card's only prop: `"anim": { "props": ["schrank"] }`. Some cards are better acted than drawn (symptoms, *Kissen* hugged by the cat): they set `"anim": { "character": "katze", … }` and are drawn by the cat with its pose, motions and props. Rule of thumb: the thing alone first, the cat now and then.

On noun cards every highlight is drawn in the gender colour, so a tip highlights only words of the same gender (`der Schrank → {{im}} Schrank`, not `die {{Ärztin}}` on a der card); other nouns stay plain.

### Buddies

A second character can appear as a prop of the first. In cat decks, Knödel is the cat's buddy: props `knoedel` (happy), `knoedel-wow`, `knoedel-tired`, `knoedel-shock`, `knoedel-flat`, `knoedel-cool`, `knoedel-pose`, `knoedel-walk`, `knoedel-bench` (asleep), `knoedel-float`, `knoedel-guest`, `knoedel-table`, `knoedel-cheers`, `knoedel-full`, `knoedel-hug` (held by the cat), `knoedel-on-pack`, `knoedel-sleep` (in bed), `knoedel-top`. Since rev. 10 also `knoedel-coach` (with a whistle), `knoedel-stretch`, `knoedel-laugh`, `knoedel-roll`, `knoedel-yoga`, `knoedel-dive`, `knoedel-snow`. Each one is a small Knödel (about a third of his own size) with a fixed expression and its own idle movement, at a fixed place (`buddy()` and `BUDDY_PROPS` in `katze.js`). The device draws him with the same shapes as the Knödel character, so no second rig is needed.

### Characters

Pose parameters belong to the character and are listed in its registry once implemented. The neutral values are in the drawing reference (`N0`).

| Character | Used for | Pose parameters | Drawing reference |
|---|---|---|---|
| `knoedel` | adjectives, expressions | `jump rot sx sy open lid happy shut lookX lookY browY browT smile mopen mw wob blush tint armL armR` | `tools/preview/knoedel.js` |
| `katze` | verbs | `jump rot sx sy open lid happy shut lookX lookY smile mopen blush earL earR tail hLx hLy hRx hRy fLx fLy fRx fRy` | `tools/preview/katze.js` |
| `dinge` | nouns | none: each object (`OBJ` entry) animates itself | `tools/preview/dinge.js` |

The cat's paws are placed by target points (`hLx/hLy`, `hRx/hRy`, body coordinates, feet at y = 0) and reached with a two-bone arm, so a pose says where the paw is, not how the arm bends. Motions move the targets (`scrub`, `push`, `sweep`), and held props follow the paws.

### Drawing reference for new ids

New motions, effects and bubbles are designed in the web preview first, and the firmware ports them from there, as it did for Ep.4. Conventions for the preview:

- Same stage as Ep.4: SVG, a 200 × 200 disc, character drawn from basic shapes (ellipses, round-capped lines, simple paths). No bitmaps, gradients or filters in anything the firmware has to draw.
- Each id is its own named entry keyed by the registry id (`MOTION["sway-slow"]`, `FX["rain-cloud"]`, `PROP["vacuum"]`, `BUBBLE["bed"]`), so it can be ported one by one.
- Reuse registry ids wherever possible. A deck should add only a few new ids; the checker lists them.

## Audio

German only, so one set serves every locale. Generated from `deck.json` by `tools/make_audio.py`:

| File | Spoken text |
|---|---|
| `<card-id>_0.mp3` | face 1: `lead` + article + `headword`: "die Wolke.", "sich anziehen." |
| `<card-id>_1.mp3` | face 2 grammar line: "stand auf. ist aufgestanden." / "die Wolken." / "stolz auf." Missing if the card has none. |
| `<card-id>_2.mp3` | face 2 example, without markup |
| `<card-id>_3.mp3` | face 3 pattern (verbs and nouns with a `pattern` only) |

So every grammar line that is displayed is also spoken, including noun plurals, whose umlauts matter. The text is defined once, in `deckfmt.spoken_lines()`. `make_audio.py` writes `audio/manifest.json` with text, provider, model, voice and file format of every file. `check_deck.py` refuses a deck whose audio is missing or whose manifest text differs from `deck.json`, e.g. after an example was edited. Only files whose text or voice changed are regenerated.

### Audio providers

| Provider | Use | Notes |
|---|---|---|
| Azure Speech (billed, with a free monthly allowance) | Default | The provider is `final` in `tools/voices.json`; key and region in `SPEECH_KEY` and `SPEECH_REGION`. Mono MP3, 24 kHz, 48 kbit/s (`output_format`). ElevenLabs (`ELEVENLABS_API_KEY`) is available as an alternative. |
| edge-tts (free) | `--provider edge` (importer: `--audio edge`) | Temporary, for trying cards out without an account. **Never committed**: while a deck's `audio/` holds any such file, `make_audio.py` keeps a `.gitignore` in that folder that hides all of it from git. |

Paying is never a side effect. For a paid provider, `make_audio.py` first prints how many files and characters it would generate and stops; it only calls the API when run again with `--paid`.

Final audio is committed to the public repository only after confirming that the provider's terms allow redistribution; its licence is stated separately from the content licence.

## Workflow

1. **Write** (content): `content/<deck-id>/deck.json`, a web preview, `tools/check_deck.py`. There is no separate review step: a mistake found later is fixed in `deck.json` (with a new `version`) and goes out in the next content pack.
2. **Import** (firmware): `python3 tools/import_decks.py`, usually run by the firmware side. Without arguments it imports every deck in `content/library.json`.
   - Shows the audio that is missing and what it would cost; generates it only with `--paid`.
   - Then runs `check_deck.py --require-audio`, compares `registry/<character>.json` with the firmware code, lays out every text of **every locale** with the firmware's own layout code and real fonts, and refuses a deck with a face that does not fit. Ids the firmware lacks are listed; the card plays without them until they are ported from the web preview. Problems go back to step 1 or into this document.
   - Writes the content pack `packs/<name>.bin` (not committed) with two locales; `--locale` (default `en`) is the one the watch starts in. `content/library.json` names the pack and lists its decks; another pack is another library file (`--library`).
   - `python3 tools/flash_content.py` writes the pack to the watch. The program is flashed separately (`idf.py flash`) and only changes when the firmware does.
